iOS 版移植方案与实施计划

把一款 Electron 沉浸式音乐播放器带到 iPhone。核心结论：前端已是纯 Web 资产，不重写视觉、不重写前端， 用 Capacitor 包壳 + 后端外置 + 原生音频插件完成移植。

文档版本 v1.0 2026-10-16 预估 13～18 人周 当前版本 v2.2.3
一句话结论

走 Capacitor 包壳（WKWebView） 路线：100% 复用现有 Web 前端（18 个 GLSL 粒子视觉、3D 歌词舞台、3D 歌单架直接可用）， 把本地 Node 服务搬到云端或用户自托管，用原生 Swift 插件补齐后台播放、锁屏控制与系统集成。 放弃原生重写（40+ 人周）与 nodejs-mobile 本地跑（被 iOS 运行时限制卡死）。

为什么不是原生重写？ 这个项目 60% 的价值在视觉层，而视觉层已经是 Web 资产（GLSL 着色器 + Three.js 场景图）。原生重写意味着把 18 个粒子预设翻译成 Metal、 重建 3D 歌词舞台与歌单架 —— 投入产出比极差。为什么不是 nodejs-mobile？iOS 禁用 JIT，Node 只能解释执行、性能腰斩， 且 go-music-api 这类平台二进制在 iOS 上根本无法运行。

3目标架构

平台差异全部收敛到一层适配层，业务代码不动。

4后端策略 · 必须先定，影响全局

现有 server/server.js 是单用户本地服务：Cookie 存内存、缓存写本地、无鉴权、无用户维度。

这是整个方案的分水岭 选「自托管」还是「官方云」，决定了后端要不要大改、版权风险落在谁头上、以及能不能上架。

若走模式二，服务化改造清单

  • 路由前置鉴权中间件：/api/* 校验 Bearer token，/api/app/version、/api/login/* 白名单放行
  • 用户会话隔离：网易云 / QQ / 酷狗 Cookie 按 userId 加密落库（AES + 独立密钥），不再写单例内存
  • 缓存分层：节拍缓存 / 封面 / 音频代理的 key 全部加 userId 前缀；音频代理走对象存储 + CDN
  • 限流与防滥用：/api/parse/music（换源，最贵）、/api/search、/api/song/url 分别限流 + 异常熔断
  • 登录改造：废弃「打开登录窗抓 Cookie」，改用项目已有的扫码登录（/api/login/qr/*、/api/kugou/login/qr/*），服务端持 Cookie 并下发 token
  • 部署：Docker 镜像 + 反向代理 + HTTPS + 健康检查 /__bhands_identity
  • 配置外置：GO_MUSIC_API_URL、代理、缓存目录全部走环境变量

6音频方案 · 最容易踩坑的地方

WKWebView 的音频在 iOS 上有明确限制，必须用原生播放器接管。

① 必须用原生播放器

WKWebView 里的 <audio> 进入后台会被系统挂起，AudioContext 也会被中断。后台播放 + 锁屏控制必须走 AVAudioSession(.playback) + AVPlayer。

② AudioContext 要手势解锁

iOS 上 AudioContext 初始为 suspended，必须绑定到真实点击事件里 resume()，否则频谱与节拍分析会静默失效。

③ 节拍链路要保住

07-beat.js 依赖 decodeAudioData 做离线预解析，原生播放器需把音频数据回灌给 Web 层（本地代理 URL 或分块传递）。

④ 系统事件要接管

MPNowPlayingInfoCenter 填元数据；MPRemoteCommandCenter 接管播放控制；来电 / 拔耳机要正确 pause/resume。

Info.plist 关键项 UIBackgroundModes: audio · NSMicrophoneUsageDescription · NSLocalNetworkUsageDescription（连接自建服务器）

7性能与功耗策略

iPhone GPU 跑「18 个 GLSL 粒子 + 3D 歌词舞台 + 3D 歌单架 + 频谱」是重负载，必须有分级。

措施具体做法
渲染分辨率renderer.setPixelRatio(Math.min(devicePixelRatio, 2))，低端机降到 1.5
粒子数分级按设备内存 / 首帧耗时动态降档（20 万 → 8 万 → 4 万）
预设分级星河 / 极光 / 万花筒 / 螺旋星云等重预设标记为高负载，低端机默认隐藏或降采样
帧率控制低电量模式或后台 → 降至 30fps 或暂停渲染循环（visibilitychange）
离屏优化不可见时停 requestAnimationFrame；歌词舞台纹理按需重建
包体积public/media 启动视频 22MB 是最大头，建议压为 H.265 或改「静态首帧 + 短动画」

8合规与分发 · 最大风险

⚠ 风险本质 项目核心卖点之一是「多音源解析」：GD音乐台、UnblockNeteaseMusic、LX Music 脚本，本质是绕过官方会员限制获取版权音乐， 且项目不是任何平台的官方客户端。App Store 审核极高概率被拒（Guideline 5.2.1 第三方内容 / 5.2.3 知识产权 / 4.7）， 官方声明「非官方客户端」不构成免责。公开分发后还可能收到版权方投诉。
